# BreachEngine — Appendix A: Component & Prop Attribute Reference

> **Provenance: Verified (plugin source).** Generated mechanically from `SerializationTools/AttributesMap` (the table the Mission Exporter validates attributes against; its header says it is itself generated by a `PropCompiler.py`). It lists **289 component/prop names and 1,746 attributes**. It tells you *names, value kinds and defaults*; it does **not** tell you what the engine *does* with them (that lives in the engine, which BreachEngine must infer or design — see the main document, §8).
>
> Regenerate this file whenever the plugin updates. Do not hand-edit.

## How to read an entry

`Attr` `(kind = default)` — `∅` means the map gives no default (nil). Defaults are shown exactly as the plugin source writes them (strings in quotes, `true/false`, numbers).

| Kind | Validator accepts | Notes |
|---|---|---|
| `num` | Lua number | |
| `int` | number with no fractional part | |
| `int?` | nil or integer | |
| `expr` | boolean, string **or** number | an *expression* in the mission expression language (main doc §9) |
| `state` | string with **no whitespace** | a *state variable name* |
| `str` | string | |
| `netid` | integer 1–999 (number, or numeric string) | hacking-network id |
| `netid-str` | `""`, a number 1–999, or any non-numeric string (expression) | |
| `bool` | boolean | |
| `bool?` | nil or boolean | |
| `color?` | nil, `Color3`, or string (key into `MissionSetup.Colors`) | |
| `material?` | nil or string (Material name) | |
| `vec3` | `Vector3` | |

**Which entry applies to an instance?** For a `BoolValue`, the entry is looked up by its **`Type` attribute**; for any other class (e.g. a `Part` or `Model`), by the instance's **`Name`**. Instances whose name/Type isn't in this table are passed through unvalidated. (Main doc §3.4.)
